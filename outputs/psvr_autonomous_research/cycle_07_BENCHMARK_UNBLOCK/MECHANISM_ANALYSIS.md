# Input-pool analysis

The decisive bottleneck is source duration and provenance, not decode availability. The pool contains 603 unique Nexar MP4s, but every one is only 15.00–49.46 seconds (at most five frozen 10-second units). H-TIE1 retains A0's 29 four-unit scan batches; a source with fewer than 117 units becomes fully observed before this progressive workload can operate. These clips therefore cannot test path-dependent partial-proxy scheduling.

`realcartest_5k` is decodable but is a documented first-5000-frame prefix of the missing `realcartest` source, so it fails independence. The long historical dataset2 bytes are absent and a later role audit identifies the camera as in-cabin/driver-facing, making the ego-path ontology inapplicable. DrivingDojo-mini contains short image-sequence sessions rather than continuous video containers. Existing output/experiment media are crops, windows, or review derivatives.

Only `long_video_dataset3` satisfies source independence, length, decode, physical proxy, and physical oracle feasibility. The highest-value next action is acquiring two forward-facing independent long source videos, not modifying an algorithm.
