# 杭州YouTube 技术规范化报告

原始 `杭州YouTube.mp4` 保留且未覆盖。原始全量解码发现大量 H.264 NAL
错误；容器 remux 虽以 exit 0 完成，但全量解码仍失败。随后完成唯一一次受控
全时轴转码（配置与日志均已保留）。

转码输出本身可完整解码，DTS 单调（14,200 packet、0 regression），且 12/12
随机寻址成功。但其持续时间仅 **473.700 秒**，而输入容器声明为 **5600.566 秒**；
仅保留 8.4581% 时间轴、丢失 91.5419%。输出帧数为 14,200，而输入容器声明
168,017 帧。

因此不满足 `NO_UNEXPLAINED_TEMPORAL_GAPS`，也无法证明完整连续源时间轴被
保留。技术恢复 Gate 为 `FAIL`，规范化副本不能替代原文件进入确认性实验。

此外，`杭州.mp4` 与原 YouTube 文件具有相同的容器时长与帧数；在 1% 和 6%
相对时间点的独立感知哈希汉明距离分别为 6/64 与 3/64。这是同源/重编码解释的
直接反证，与两段视频“不同录制 session”的负责人声明冲突。该内容同一性问题
独立于解码失败，也阻止它们构成两个独立确认性视频。
